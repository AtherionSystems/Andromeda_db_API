RESUMEN
-------
Antes de esta implementación, todos los endpoints de la API eran completamente
públicos — cualquiera podía abrir una URL en el navegador y ver los datos.
Esta guía documenta cada cambio realizado para asegurar el backend usando JWT
(JSON Web Tokens) sin modificar la base de datos.

El flujo de autenticación es:
  1. El cliente hace POST con las credenciales a /api/auth/login
  2. El backend valida las credenciales contra la BD (comparación con hash BCrypt)
  3. En caso de éxito, el backend devuelve los datos del usuario + un JWT firmado
  4. El cliente almacena el token y lo envía en cada request subsecuente:
       Authorization: Bearer <token>
  5. Spring Security valida el token en cada request antes de llegar a cualquier controller


================================================================================
CAMBIOS EN EL BACKEND
================================================================================

1. pom.xml
----------
ELIMINADO:
  spring-security-crypto
  (se usaba solo para BCrypt — sin seguridad HTTP)

AGREGADO:
  spring-boot-starter-security
  (cadena de filtros HTTP completa de Spring Security)

  io.jsonwebtoken:jjwt-api:0.12.6
  io.jsonwebtoken:jjwt-impl:0.12.6        (runtime)
  io.jsonwebtoken:jjwt-jackson:0.12.6     (runtime)
  (librería JJWT para generar y validar tokens JWT)


2. application.properties
--------------------------
AGREGADO:
  jwt.secret=${JWT_SECRET}
  jwt.expiration.ms=86400000

  JWT_SECRET debe establecerse como variable de entorno.
  Debe ser un string en Base64 que decodifique a al menos 32 bytes (256 bits).

  Para generar un secreto válido en PowerShell:
    $bytes = New-Object byte[] 32
    [System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
    [Convert]::ToBase64String($bytes)

  La expiración del token es 86400000 ms = 24 horas.


3. ARCHIVO NUEVO: src/main/java/com/atherion/andromeda/security/JwtUtil.java
------------------------------------------------------------------------------
Responsable de:
  - generateToken(User user)
      Construye un JWT firmado con claims: subject (username), userId, userType.
      Firma con HMAC-SHA256 usando la clave JWT_SECRET.

  - extractUsername(String token)
      Parsea el token y devuelve el subject (username).

  - isTokenValid(String token)
      Devuelve true si el token está bien formado, firmado correctamente y no expiró.


4. ARCHIVO NUEVO: src/main/java/com/atherion/andromeda/security/JwtAuthFilter.java
-----------------------------------------------------------------------------------
Un OncePerRequestFilter de Spring que se ejecuta en cada request HTTP entrante.

Lógica:
  - Lee el header Authorization.
  - Si el header está ausente o no comienza con "Bearer ", la request continúa
    sin autenticación (será bloqueada por la configuración de Security si el
    endpoint requiere auth).
  - Si el token está presente y es válido, establece el usuario autenticado en el
    SecurityContext de Spring para que la request sea autorizada.


5. MODIFICADO: src/main/java/com/atherion/andromeda/config/SecurityConfig.java
-------------------------------------------------------------------------------
Antes: solo declaraba un bean BCryptPasswordEncoder. Sin seguridad HTTP.

Después: configuración completa de SecurityFilterChain:
  - CSRF deshabilitado (no se necesita para APIs REST sin estado)
  - CORS configurado a través de Spring Security (usa el CorsConfig.java existente)
  - Gestión de sesión en modo STATELESS (sin sesiones en servidor, solo JWT)
  - Endpoints públicos (no requieren token):
      /api/auth/**        (login, registro)
      /actuator/health    (health check para OCI)
  - Todos los demás endpoints requieren un JWT válido
  - JwtAuthFilter se inserta antes del filtro de autenticación por defecto de Spring


6. ARCHIVO NUEVO: src/main/java/com/atherion/andromeda/dto/LoginResponse.java
------------------------------------------------------------------------------
Nuevo DTO de respuesta para el endpoint de login.

Campos (planos, sin anidación):
  token        — el string JWT firmado
  id
  name
  username
  email
  phone
  userTypeId
  userType
  createdAt

Este DTO reemplazó el retorno de UserResponse desde el login, que no tenía campo token.


7. MODIFICADO: src/main/java/com/atherion/andromeda/controllers/AuthController.java
------------------------------------------------------------------------------------
- Se agregó JwtUtil como dependencia.
- El endpoint de login ahora devuelve LoginResponse.from(user, jwtUtil.generateToken(user))
  en lugar de UserResponse.from(user).
- El endpoint de registro no cambió (sigue devolviendo UserResponse, sin token).

CAMBIOS REQUERIDOS EN EL FRONTEND
================================================================================

1. types/api.ts
   Agregar el campo token a ApiUser:
     token: string

2. Después del login, almacenar el token:
     localStorage.setItem("token", user.token)

3. Cliente apiFetch (client.ts o equivalente)
   Adjuntar el token en cada request:
     const token = localStorage.getItem("token")
     if (token) headers["Authorization"] = `Bearer ${token}`


================================================================================
VARIABLES DE ENTORNO
================================================================================

Variable          Dónde se usa       Notas
--------------    ---------------    ------------------------------------------
JWT_SECRET        Backend (.env)     String Base64, decodifica a >= 32 bytes.
                                     Puede tener valores distintos por entorno,
                                     pero tokens de un entorno no funcionan en otro.

TELEGRAM_BOT_TOKEN     .env          Usar token del bot de dev para desarrollo local.
TELEGRAM_BOT_USERNAME  .env          Usar username del bot de dev para desarrollo local.


================================================================================
DESARROLLO LOCAL vs PRODUCCIÓN EN OCI
================================================================================

Para evitar el conflicto 409 de Telegram (solo se permite una sesión de long-poll
por token), usa un bot separado para desarrollo local:

.env local:
  TELEGRAM_BOT_TOKEN=<token del bot andromedadevbot>
  TELEGRAM_BOT_USERNAME=andromedadevbot

Variables de entorno en OCI:
  TELEGRAM_BOT_TOKEN=<token del bot de producción>
  TELEGRAM_BOT_USERNAME=<username del bot de producción>

Ambos entornos pueden correr simultáneamente sin conflictos.


================================================================================
PRUEBAS
================================================================================

1. Verificar que el endpoint está protegido (debe devolver 403):
   Abrir cualquier URL de datos en Chrome, ej.: http://localhost:8080/api/projects

2. Hacer login y obtener el token (PowerShell):
   $body = '{"username":"youruser","password":"yourpass"}'
   $response = Invoke-RestMethod -Uri "http://localhost:8080/api/auth/login" `
               -Method POST -Body $body -ContentType "application/json"
   $token = $response.token
   echo $token

3. Acceder a un endpoint protegido con el token:
   $headers = @{ Authorization = "Bearer $token" }
   Invoke-RestMethod -Uri "http://localhost:8080/api/projects" `
                     -Method GET -Headers $headers

   Resultado esperado: datos devueltos normalmente.

4. Corregir los tests (el test de carga de contexto fallará sin JWT_SECRET):
   Agregar en src/test/resources/application.properties:
     jwt.secret=dGVzdHNlY3JldGtleWZvcnVuaXR0ZXN0aW5nb25seQ==


================================================================================
NOTAS
================================================================================

- No se realizaron cambios en la base de datos. JWT es completamente sin estado.
- Las contraseñas ya se almacenaban como hashes BCrypt en la BD desde antes.
- La respuesta 403 (en lugar de 401) para tokens ausentes es el comportamiento
  por defecto de Spring Security cuando no hay AuthenticationEntryPoint configurado.
  Funcionalmente sigue bloqueando el acceso. Se puede cambiar agregando:
    .exceptionHandling(ex -> ex
        .authenticationEntryPoint((req, res, e) ->
            res.sendError(HttpServletResponse.SC_UNAUTHORIZED, "Unauthorized")))
  al SecurityFilterChain en SecurityConfig.java.
