1. RESUMEN EJECUTIVO
────────────────────────────────────────────────────────────────────────────────

Andromeda Backend API es una plataforma de gestión de proyectos en Spring Boot 4
que expone una API REST completa para administrar proyectos, tareas, sprints,
usuarios y miembros del equipo, respaldada por una Oracle Autonomous Database.

El equipo de desarrollo identificó un punto de fricción recurrente: los interesados
y desarrolladores tenían que memorizar la sintaxis exacta de los slash-commands para
interactuar con el bot de Telegram (ej. /tasks 3, /sprinttasks 2), lo que creaba una
barrera de adopción y reducía la utilidad del bot como dashboard de proyecto en tiempo real.

Para resolver esto, se integró directamente una capa de IA con lenguaje natural dentro
del bot de Telegram. Esta capa intercepta cualquier mensaje de forma libre del usuario
(que no comience con un slash-command), lo envía a un modelo de lenguaje grande (LLM)
a través de la API de Groq, y le pide al modelo que clasifique la intención del usuario
y la mapee al comando interno correcto — de forma transparente, sin que el usuario
necesite conocer la existencia del comando.

Esta decisión arquitectónica aporta tres beneficios concretos:

  1. Accesibilidad — Cualquier miembro del equipo puede consultar el estado del proyecto
     en español o inglés simple sin consultar una referencia de comandos. Un mensaje
     como "show me tasks in project 2" o "¿cuáles son los sprints del proyecto 5?"
     es comprendido y respondido automáticamente.

  2. Análisis Aumentado por IA — Más allá del enrutamiento, el bot expone tres comandos
     de análisis potenciados por IA (/suggest, /analyze, /fix) que envían métricas
     reales del proyecto al LLM y devuelven recomendaciones accionables, puntuaciones
     de salud y guías de resolución de tareas — convirtiendo el bot en un asesor
     inteligente de proyectos, no solo una herramienta de consulta de datos.

  3. Costo de Infraestructura Cero — La capa de IA funciona a través de la API de Groq
     (compatible con OpenAI, pago por uso) y se activa/desactiva con una sola variable
     de entorno (AGENT_AI_ENABLED). El sistema degrada graciosamente al modo
     solo-slash-commands cuando la IA está deshabilitada, sin requerir cambios de código.


2. PROMPT DE SISTEMA VERBATIM — ROUTER DE INTENCIÓN EN LENGUAJE NATURAL
────────────────────────────────────────────────────────────────────────────────

Archivo fuente: src/main/java/com/atherion/andromeda/telegram/AiIntentRouter.java
Campo: SYSTEM_PROMPT (private static final String)

El siguiente prompt se envía como mensaje de rol "system" en cada request de
lenguaje natural recibida por el bot de Telegram. El mensaje crudo del usuario
se envía como mensaje de rol "user" junto a él.

--- INICIO DEL PROMPT ---

You are a routing assistant for the Andromeda project management Telegram bot.
Given a natural language message from a user, map it to the closest matching bot command.

Available commands:
  /projects                   — list all projects
  /project <id>               — project details
  /tasks <projectId>          — list tasks in a project
  /task <id>                  — task details
  /members <projectId>        — list project members
  /sprints <projectId>        — list project sprints
  /sprinttasks <projectId>    — sprint task board
  /users                      — list all users
  /user <id>                  — user details
  /suggest <projectId>        — AI suggestions for a project
  /analyze <projectId>        — AI health analysis of a project
  /fix <taskId>               — AI guidance to resolve a task
  /pingai                     — test AI backend connectivity

Rules:
- Respond ONLY with a JSON object; no markdown, no explanation, no extra text.
- If the message maps to a command: {"cmd": "/command_name", "args": "arguments_here"}
- If args are empty, use: {"cmd": "/command_name", "args": ""}
- If you cannot map the message to any command: {"cmd": "none", "args": ""}

--- FIN DEL PROMPT ---


3. PROMPTS DE SISTEMA ADICIONALES (Handlers de Comandos AI)
────────────────────────────────────────────────────────────────────────────────

Archivo fuente: src/main/java/com/atherion/andromeda/telegram/BotCommandHandler.java

Los siguientes prompts son usados por los comandos de análisis AI dedicados. En cada
caso, el contexto del usuario (métricas del proyecto, detalles de la tarea) se ensambla
con datos reales de la base de datos y se envía como mensaje de rol "user".

3a. /suggest <projectId> — Sugerencias de Mejora
    Prompt de sistema (verbatim):
    "You are a project management expert for the Andromeda system. "
    "Analyze the project data and give 3-5 concise, actionable suggestions to improve project health. "
    "Format as a numbered list. Be specific and practical."

3b. /analyze <projectId> — Análisis de Salud
    Prompt de sistema (verbatim):
    "You are a project health analyst for the Andromeda system. "
    "Given the project metrics, provide: 1) an overall health score (0-10), "
    "2) top 2-3 risks identified, 3) one key recommendation. "
    "Be concise — maximum 200 words."

3c. /fix <taskId> — Guía de Resolución de Tarea
    Prompt de sistema (verbatim):
    "You are a technical project management assistant for the Andromeda system. "
    "Given a task description, provide practical, step-by-step guidance on how to approach, "
    "implement, or resolve it. Be specific and actionable. Maximum 150 words."

3d. Debug / Passthrough Directo (activado por la palabra clave "guacamole")
    Prompt de sistema (verbatim):
    "You are a helpful assistant. Answer any question the user asks clearly and concisely."

3e. /pingai — Prueba de Conectividad
    Prompt de sistema (verbatim):
    "You are a test assistant."
    Mensaje de usuario (verbatim):
    "Reply with exactly one word: pong"


4. CONFIGURACIÓN DE IA DENTRO DEL PROYECTO SPRING BOOT
────────────────────────────────────────────────────────────────────────────────

4a. Clase de Propiedades
    Archivo: src/main/java/com/atherion/andromeda/config/AiProperties.java
    Prefijo: agent.ai
    Campos y valores por defecto:
      enabled  = true                          (boolean)
      baseUrl  = "https://api.groq.com/openai/v1"  (String)
      apiKey   = (ninguno — debe inyectarse)   (String)
      model    = "qwen/qwen3-32b"              (String)

4b. Bindings en application.properties
    Archivo: src/main/resources/application.properties

      agent.ai.enabled=${AGENT_AI_ENABLED}
      agent.ai.base-url=${AGENT_AI_BASE_URL}
      agent.ai.api-key=${AGENT_AI_API_KEY}
      agent.ai.model=${AGENT_AI_MODEL}

    Los cuatro valores se inyectan en runtime mediante variables de entorno,
    manteniendo los secretos fuera del control de versiones.

4c. Capa de Servicio
    Archivo: src/main/java/com/atherion/andromeda/services/AiService.java
    - Usa el RestClient de Spring contra la baseUrl configurada.
    - Envía requests de /chat/completions compatibles con OpenAI (funciona con
      cualquier proveedor compatible con OpenAI, no solo Groq).
    - Elimina automáticamente los bloques de scratchpad <think>...</think>
      producidos por modelos de razonamiento como Qwen3 en modo thinking.
    - Expone tres métodos públicos:
        chat(systemPrompt, userMessage)  → String (respuesta en texto plano)
        chatJson(systemPrompt, userMessage) → JsonNode (JSON estructurado)
        ping()                           → long (latencia en ms, -1 si falla)

4d. Router de Intención
    Archivo: src/main/java/com/atherion/andromeda/telegram/AiIntentRouter.java
    - Llama a aiService.chatJson() con el prompt de enrutamiento (Sección 2).
    - Parsea el JSON retornado {"cmd": "...", "args": "..."}.
    - Delega a BotCommandHandler.handle() con el comando resuelto.
    - Devuelve null (el bot permanece en silencio) cuando no se reconoce ninguna intención.

4e. Punto de Entrada del Bot
    Archivo: src/main/java/com/atherion/andromeda/telegram/AndromedaBot.java
    - Extiende TelegramLongPollingBot.
    - Lógica de enrutamiento de mensajes:
        • Comienza con "/"         → BotCommandHandler (slash-command directo)
        • Contiene "guacamole"    → handleDirectAiQuestion() (passthrough a IA)
        • Cualquier otro texto    → AiIntentRouter.route() (enrutamiento NL)
        • IA deshabilitada + sin "/" → ignorado silenciosamente

4f. Configuración del Bot de Telegram
    Archivo: src/main/resources/application.properties
      telegram.bot.token=${TELEGRAM_BOT_TOKEN}
      telegram.bot.username=${TELEGRAM_BOT_USERNAME}

4g. Variables de Entorno Requeridas (resumen)
    Variable                    Propósito
    ─────────────────────────── ───────────────────────────────────────────
    AGENT_AI_ENABLED            "true" o "false" — switch maestro de IA
    AGENT_AI_BASE_URL           URL base de la API (ej. https://api.groq.com/openai/v1)
    AGENT_AI_API_KEY            Clave de API del proveedor (secreto)
    AGENT_AI_MODEL              ID del modelo (ej. qwen/qwen3-32b)
    TELEGRAM_BOT_TOKEN          Token de @BotFather
    TELEGRAM_BOT_USERNAME       Username del bot (sin @)
    DB_USERNAME                 Usuario de Oracle DB
    DB_PASSWORD                 Contraseña de Oracle DB
    WALLET_PATH                 Ruta al directorio del wallet de Oracle
    WALLET_TRUSTSTORE_PASSWORD  Contraseña del truststore JKS
    WALLET_KEYSTORE_PASSWORD    Contraseña del keystore JKS


4h. Sobre el Proveedor de IA y el Modelo
    ──────────────────────────────────────────────────────────────────────────

    GROQ (Proveedor de API)
    Groq es una empresa de infraestructura de IA que diseñó su propio chip —
    la Language Processing Unit (LPU) — específicamente para ejecutar inferencia
    de modelos de lenguaje grande. A diferencia de los proveedores basados en GPU,
    la arquitectura LPU está optimizada para la naturaleza secuencial y limitada
    por memoria de la generación de tokens, lo que resulta en velocidades de
    inferencia típicamente 10–20x más rápidas que despliegues equivalentes en GPU.
    Para un bot de Telegram en tiempo real donde los usuarios esperan respuestas
    casi instantáneas, esta ventaja de latencia es significativa.

    Groq expone una API REST compatible con OpenAI (mismo esquema de request/response
    que el endpoint /chat/completions de OpenAI), por lo que AiService funciona con
    cualquier proveedor compatible con OpenAI sin cambios de código — cambiar de
    proveedor es un cambio de una sola variable de entorno (AGENT_AI_BASE_URL).
    Groq opera con un generoso nivel gratuito, lo que lo hace apropiado para
    proyectos académicos y prototipos antes de comprometerse con un presupuesto
    de inferencia de pago.

    QWEN3-32B (Modelo)
    Qwen3 es la tercera generación de la familia de modelos de lenguaje grande
    de pesos abiertos Qwen, desarrollada y publicada por Alibaba Cloud. La
    variante "32b" tiene 32 mil millones de parámetros, ubicándola en el nivel
    medio-alto de los modelos abiertos — suficientemente grande para razonamiento
    sólido y seguimiento de instrucciones, suficientemente pequeño para ejecutarse
    eficientemente en el clúster LPU de Groq.

    Características clave relevantes para Andromeda:

      • Modo thinking — Los modelos Qwen3 soportan un modo de razonamiento de
        cadena de pensamiento opcional donde el modelo emite un scratchpad
        <think>...</think> antes de su respuesta final. AiService.extractContent()
        elimina automáticamente este bloque para que los usuarios nunca vean trazas
        de razonamiento crudas. Este modo mejora la precisión en decisiones de
        enrutamiento complejas a costa de un pequeño aumento de latencia.

      • Fortaleza multilingüe — Qwen3 fue entrenado en un corpus multilingüe
        extenso con énfasis particular en chino, inglés y español, lo que lo hace
        muy adecuado para un equipo que se comunica principalmente en español.
        El router de intención maneja consultas en español de forma natural
        (ej. "muéstrame las tareas del proyecto 3") de manera confiable.

      • Seguimiento de instrucciones — El modelo obtiene altas puntuaciones en
        benchmarks de salida JSON y adherencia a instrucciones, lo que es crítico
        para el router de intención cuya correctitud depende completamente de que
        el modelo devuelva un objeto {"cmd": "...", "args": "..."} bien formado
        y nada más.

      • Pesos abiertos — Los pesos de Qwen3 están disponibles públicamente bajo
        una licencia permisiva, lo que significa que el equipo podría auto-hospedar
        el modelo en infraestructura GPU local o institucional en el futuro,
        eliminando completamente la dependencia de la API externa de Groq.


5. PRÓXIMOS PASOS — HOJA DE RUTA DE IMPLEMENTACIÓN DE IA
────────────────────────────────────────────────────────────────────────────────

La integración actual de IA establece una base sólida. Los siguientes pasos
representan la progresión natural para profundizar las capacidades de IA dentro
de la plataforma Andromeda, ordenados aproximadamente por complejidad de implementación.

5a. Extender el Enrutamiento de Lenguaje Natural a Comandos de Escritura
    Actualmente, el router de intención solo mapea mensajes a comandos de lectura.
    Las operaciones de escritura (crear tareas, sprints, proyectos, actualizar estados)
    todavía requieren sintaxis explícita de slash-command y una cuenta vinculada.
    Siguiente paso: expandir el SYSTEM_PROMPT en AiIntentRouter para incluir todos los
    comandos de escritura, y enseñar al router a extraer argumentos estructurados del
    lenguaje natural (ej. "crea una tarea llamada Login Page en el proyecto 3, 2 horas,
    prioridad alta" → /newtask 3 | Login Page | 2 | 5 | high).
    La barrera de autenticación /link ya existe; el router solo necesita ser informado
    sobre los comandos de escritura y sus formatos de argumento.

5b. Memoria Conversacional / Contexto Multi-Turno
    Cada mensaje es actualmente sin estado — la IA no tiene memoria de lo que se
    dijo antes en una conversación. Esto significa que un usuario no puede hacer
    preguntas de seguimiento como "¿y qué pasa con el proyecto 4?" después de
    preguntar sobre el proyecto 3.
    Siguiente paso: introducir un almacén de historial de conversación por usuario
    (mapa en memoria o Redis) en AiIntentRouter que acumule los últimos N pares de
    mensajes (usuario + asistente) y los incluya en el array messages[] enviado a
    la API. Esto habilita preguntas de seguimiento naturales y enrutamiento contextual.

5c. Notificaciones Proactivas de IA
    El bot actualmente es reactivo — solo responde cuando se le envía un mensaje.
    El endpoint AiNotifyController ya existe (src/main/java/.../controllers/
    AiNotifyController.java) como punto de entrada para webhooks.
    Siguiente paso: agregar un job programado (Spring @Scheduled) que corra cada noche,
    llame a handleAnalyze() para cada proyecto activo, y envíe un mensaje de Telegram
    a los dueños del proyecto solo cuando la puntuación de salud cae por debajo de un
    umbral configurable. Esto convierte al bot en un monitor proactivo de riesgos.

5d. Descomposición de Tareas Potenciada por IA
    El bot ya aplica el límite de 4 horas por tarea y le dice al usuario cuántas
    subtareas crear. Sin embargo, el usuario todavía tiene que nombrarlas y crearlas manualmente.
    Siguiente paso: agregar un comando /decompose <taskId> que envíe el título, la
    descripción y los criterios de aceptación de la tarea a la IA y le pida generar
    una lista lista para usar de subtareas (cada una ≤ 4 h), que el bot luego crea
    automáticamente mediante la lógica handleNewTask() existente.

5e. Planificación de Sprint Generada por IA
    Cuando se crea un nuevo sprint, el bot actualmente no hace nada más allá de
    persistir el registro.
    Siguiente paso: agregar un comando /planSprint <sprintId> que reúna todas las
    tareas pendientes del proyecto (ordenadas por prioridad y story points), las
    presente a la IA junto con el objetivo del sprint y la capacidad del equipo,
    y reciba una lista sugerida de selección y asignación de tareas. El bot puede
    entonces aplicar el plan con confirmación del usuario.

5f. Resumen Diario / Semanal Automatizado
    Siguiente paso: un mensaje de resumen programado que se envíe cada mañana al
    grupo de Telegram de cada proyecto. El resumen incluiría: tareas completadas ayer,
    tareas con vencimiento hoy, items vencidos, y un comentario de una línea de IA
    sobre la velocidad del equipo. Reutiliza la salida de handleAnalyze() y el
    mecanismo sendText() existente sin nueva ingeniería de prompts requerida.

5g. Búsqueda Semántica entre Tareas y Proyectos
    El comando /tasks actual devuelve todas las tareas de un proyecto como una lista
    plana. Para proyectos grandes esto es ruidoso y difícil de escanear.
    Siguiente paso: agregar un comando /search <query> que envíe la consulta y todos
    los títulos/descripciones de tareas a la IA y le pida devolver las 5 tareas más
    relevantes ordenadas por similitud semántica con la consulta. Esto evita la
    necesidad de una base de datos vectorial aprovechando la comprensión propia del LLM.

5h. Evaluación de Modelos y Pruebas A/B
    El modelo está actualmente fijado a qwen/qwen3-32b mediante variable de entorno.
    No existe medición de la precisión de enrutamiento ni de la satisfacción del usuario.
    Siguiente paso: agregar una tabla de log ligera (ai_request_log) que registre cada
    mensaje en lenguaje natural, el comando resuelto, y si el usuario lo corrigió
    (es decir, envió un slash-command inmediatamente después). Este dataset puede usarse
    para evaluar si cambiar de modelo (ej. llama3-70b, mixtral) mejora la precisión
    de enrutamiento para entradas en español, que es el idioma principal del equipo.

5i. Panel de Chat en la Web UI
    La capa de IA actualmente solo es accesible a través de Telegram.
    Siguiente paso: exponer un endpoint REST /api/ai/chat (similar al patrón
    AiNotifyController existente) que acepte un cuerpo JSON con userId y mensaje,
    lo ejecute a través de AiIntentRouter, y devuelva la respuesta estructurada.
    Un panel de chat simple en el proyecto frontend puede entonces incorporar
    la misma experiencia de lenguaje natural directamente en el dashboard web.
